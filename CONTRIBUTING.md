# Contributing

Thanks for helping improve the Claude Security Skills Toolkit. Contributions should make authorized defensive security work more accurate, safer, easier to reproduce, or easier to understand.

## Before opening a pull request

Read the repository README, `PROMPT.md`, `SECURITY.md`, and `THIRD_PARTY_NOTICES.md`. Keep changes focused. Preserve upstream attribution and licensing. Do not add credentials, live target data, destructive payloads, unauthorized scanning instructions, or scripts that weaken sandboxing and permission boundaries.

## Good contributions

Useful contributions include better false-positive calibration, safer reproduction guidance, regression tests, language-specific secure-coding examples, install documentation, CI validation, and improvements to the audit-to-patch workflow.

## Pull requests

Explain the problem, the intended behavior, the files changed, and the validation performed. For a security change, include the affected trust boundary, evidence, impact, and how the patch was independently checked. Keep unrelated formatting or refactoring out of the same pull request.
